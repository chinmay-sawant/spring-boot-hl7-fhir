Where the data lives and moves

Select a layer to see what it does. The key fact: the app never writes to the public HAPI server. H2 holds the bundled samples; the live fetch is read-only comparison.

Boot sequenceSpring starts → JPA creates 4 tables (patients, observations, encounters, practitioners) → FhirLoaderService parses fhir-samples/*.json with the HAPI R4 parser → rows saved once (idempotent on fhirId) → log line loaded 2 patients, 2 observations, 1 encounters, 1 practitioners.
Request pathcurl → controller (params, error envelope) → service (HAPI parse/query logic) → repository (H2) → canonical FHIR JSON back. HL7v2 requests additionally pass through the HAPI v2 PipeParser.
