FHIR vs HL7v2 in one table

HL7v2 (ADT^A01 here)FHIR R4 (Patient, Observation, …)
ShapeFlat pipe-delimited segments: MSH header, PID patient, PV1 visit. Fields by position (PID-5 = name).REST + JSON resources with coded meaning. Observation.code is a LOINC code; subject.reference links Patient/patient-1.
LinkingImplicit: one message carries one visit.Explicit references: Observation → Patient, Encounter → Patient + Practitioner.
Separators| field, ^ component, ~ repetition, & sub-component. See the raw adt-a01.hl7 file.JSON structure; no positional parsing. Field names carry the meaning.
AnalogyA fax that always arrives in the same layout.A web API with typed, linkable records.
In this demoadt-a01.hl7 parses to MSH/PID/PV1 fields.Six JSON files load into H2 and serve over REST.

Key vocabulary

TermMeaning
LOINCUniversal code system for lab tests. 718-7 = Hemoglobin in Blood. Carried in Observation.code.
MSH / PID / PV1 / EVNHL7v2 segments: message header, patient identity, patient visit, event type.
ADT^A01Admit/visit notification: message type ADT, trigger event A01 (admit).
Reference (Patient/patient-1)How FHIR resources point at each other - the replacement for HL7v2's implicit bundling.
Cardinality (1..1)How many times a field may appear. Observation.status is 1..1 (required) - delete it and validation fails.
