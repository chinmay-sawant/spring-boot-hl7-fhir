The HL7 v2 pipeline, stage by stage

Inbound HL7 v2 traffic is the point of the platform, and none of it is built yet. The healthcare-hl7 module compiles, but every package inside it holds only a package-info.java placeholder. This page walks the design from plans/spring-boot/02-hl7-admissions.md: click the message fields and pipeline stages to see what each piece is supposed to do and where the code will live.

How to read planned pages Names like Hl7ParserService or PatientHl7Mapper come from the plans. They do not exist in the repository today. Everything about message anatomy (segments, fields, mappings) is fixed HL7 v2.5.1 semantics, so that part is safe to rely on.

The seven planned stages

Click a stage to see the intent, the plan reference, and the class names reserved for it.

Two acknowledgment modes

Selected with hl7.ack.mode (planned key, default not yet decided in code). MSA-1 carries AA (accepted), AE (error), or AR (rejected); MSA-2 always echoes the original MSH-10.

One application ACK

The receiver processes the message first, then answers once with the final result. Simple, but a slow FHIR submission holds the sending system's connection.

HIS ── ADT^A01 ──▶ receiver
                 │ parse · validate · persist · process
◀── ACK  MSA|AA|MSG00001
        (final application result)

Acceptance ACK, then final ACK

An acceptance ACK goes out once the message is validated and recorded. A second ACK carries the application outcome after the FHIR work. The acceptance ACK never claims the workflow succeeded.

HIS ── ADT^A01 ──▶ receiver
◀── ACK  MSA|AA|MSG00001     (accepted and recorded)
                 │ map · submit transaction Bundle
◀── ACK  MSA|AA|MSG00001     (application outcome)

Where a message can sit

The durable record is a row in inbound_messages, unique on (source_system, message_control_id). Replay of a completed message returns the prior outcome without repeating the work.

RECEIVED→ VALIDATED→ PROCESSING→ COMPLETED

Plan 04 adds RETRY_PENDING (bounded retries with backoff) and QUARANTINED (permanent failures set aside for inspection). The column accepts all six values already; the transitions are future work.
